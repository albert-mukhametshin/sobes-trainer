# Локальный ASR-сервис

FastAPI-адаптер запускает `GigaAM-v3 e2e_rnnt` на Mac и отдаёт Symfony расшифровку каждого вопроса, таймкоды слов, паузы и речевые метрики. Код Symfony зависит от `AsrProviderInterface`, поэтому GigaAM можно заменить другим движком без изменения очереди и интерфейса.

## Установка на macOS

```bash
brew install ffmpeg uv ollama
cd local-ai
uv sync
ollama pull qwen3.5:9b-q4_K_M
```

Python-зависимость GigaAM закреплена на конкретном commit официального репозитория. Веса GigaAM автоматически загружаются в пользовательский кеш при первом распознавании.

## Запуск

Из корня проекта:

```bash
make ai-asr
```

В отдельном терминале:

```bash
make ai-ollama
```

Проверка ASR без загрузки модели:

```bash
curl http://localhost:8091/health
```

## Переменные

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AUDIO_STORAGE_DIR` | `../var/audio` | Абсолютный путь к закрытому хранилищу записей |
| `LOCAL_AI_TOKEN` | `local-interview-trainer` | Bearer-токен между Symfony и FastAPI |
| `LOCAL_ASR_MODEL` | `v3_e2e_rnnt` | Модель GigaAM |
| `GIGAAM_DEVICE` | `auto` | `auto`, `mps` или `cpu`; при ошибке MPS есть автоматический fallback на CPU |
| `OLLAMA_MODEL` | `qwen3.5:9b-q4_K_M` | 4-bit модель оценки в Ollama |

Сервис слушает `0.0.0.0:8091`, чтобы Docker-контейнер Symfony мог обратиться к нему через `host.docker.internal`. Доступ к распознаванию защищён токеном. В имя аудио запрещено передавать пути.

## Порядок использования памяти

1. FastAPI лениво загружает GigaAM и последовательно распознаёт сегменты до 20 секунд.
2. В блоке `finally` GigaAM удаляется, запускаются сборщик мусора и очистка MPS/CUDA-кеша.
3. Только после возврата HTTP-ответа Symfony меняет статус на `evaluating` и вызывает Ollama.
4. После оценки всех вопросов Symfony отправляет `keep_alive: 0`, чтобы выгрузить Qwen.

Одновременно две модели этим конвейером не удерживаются. Если запустить другие приложения Ollama или отдельный ASR-процесс, их память уже находится вне контроля проекта.
