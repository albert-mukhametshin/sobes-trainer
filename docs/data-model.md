# Хранение данных тренера собеседований

## Общая схема

```text
question >── training_question ──< training >── training_session ──< training_session_segment >── question
   │                                                │                       │
   └── question_evaluation_rubric                   │                       ├── training_session_transcript
                                                    │                       └── training_session_evaluation
                                                    └── var/audio/<случайное-имя>.<расширение>
```

## Таблицы

### `question`

База технических вопросов и текущий прогресс пользователя.

| Поле | Тип | Что хранится |
|---|---|---|
| `id` | integer | Идентификатор вопроса |
| `category` | varchar(50) | Машинный код категории: `php`, `symfony`, `mysql` и т. п. |
| `category_label` | varchar(80) | Отображаемое название категории |
| `category_color` | varchar(7) | Цвет категории в формате `#RRGGBB` |
| `title` | varchar(500) | Формулировка вопроса |
| `level` | varchar(30) | Уровень сложности |
| `memory` | smallint | Качество запоминания от 0 до 100 |
| `repeats` | smallint | Количество выполненных повторений |
| `hint` | text | Рекомендация по структуре ответа |
| `last_answered_at` | timestamp, nullable | Дата последнего ответа |
| `created_at` | timestamp | Дата добавления вопроса |

### `training`

Сохранённые пользовательские тренировки.

| Поле | Тип | Что хранится |
|---|---|---|
| `id` | integer | Идентификатор тренировки |
| `name` | varchar(120) | Название тренировки |
| `best_score` | smallint, nullable | Лучший процент прохождения |
| `created_at` | timestamp | Дата создания |
| `updated_at` | timestamp | Дата последнего изменения |

### `training_question`

Связь многие-ко-многим между тренировками и вопросами.

| Поле | Тип | Что хранится |
|---|---|---|
| `training_id` | integer, FK | Ссылка на `training.id` |
| `question_id` | integer, FK | Ссылка на `question.id` |

Пара полей является составным первичным ключом, поэтому один вопрос нельзя добавить в одну тренировку дважды. При удалении тренировки связи удаляются каскадно; вопрос с существующей связью удалить нельзя случайно.

### `training_session`

Каждая попытка прохождения тренировки и сведения о единственной общей аудиозаписи этой попытки.

| Поле | Тип | Что хранится |
|---|---|---|
| `id` | integer | Идентификатор попытки |
| `training_id` | integer, FK | Какая тренировка проходилась |
| `status` | varchar(20) | `recording`, `completed` или `cancelled` |
| `started_at` | timestamp | Время начала |
| `finished_at` | timestamp, nullable | Время завершения |
| `elapsed_seconds` | integer | Продолжительность в секундах |
| `answered_count` | smallint | Сколько вопросов пройдено |
| `score` | smallint, nullable | Итоговый процент прохождения |
| `audio_filename` | varchar(180), nullable | Случайное внутреннее имя файла без исходного пути |
| `audio_mime_type` | varchar(80), nullable | MIME-тип записи, например `audio/webm` |
| `audio_size` | integer, nullable | Размер записи в байтах |
| `analysis_status` | varchar(20) | `not_started`, `queued`, `transcribing`, `evaluating`, `completed` или `failed` |
| `analysis_score` | smallint, nullable | Средняя AI-оценка всех ответов от 0 до 100 |
| `analysis_error_code` | varchar(80), nullable | Стабильный машинный код последней ошибки, например `llm_loop_after_retries` |
| `analysis_error_message` | text, nullable | Безопасное русское сообщение для интерфейса |
| `analysis_started_at` | timestamp, nullable | Начало последней попытки анализа |
| `analysis_completed_at` | timestamp, nullable | Завершение анализа или момент окончательной ошибки |

### `training_session_segment`

Таймкоды отдельных ответов внутри общей записи попытки. Порядок сегментов уникален в пределах одной попытки.

| Поле | Тип | Что хранится |
|---|---|---|
| `id` | integer | Идентификатор сегмента |
| `training_session_id` | integer, FK | Ссылка на попытку; при удалении попытки сегменты удаляются каскадно |
| `question_id` | integer, FK, nullable | Ссылка на текущую запись вопроса; при удалении вопроса становится `NULL` |
| `position` | smallint | Порядковый номер вопроса в попытке, начиная с нуля |
| `question_title` | varchar(500) | Снимок формулировки вопроса на момент прохождения |
| `category_label` | varchar(80) | Снимок отображаемой категории |
| `started_at_ms` | integer | Начало ответа относительно начала аудио, в миллисекундах |
| `ended_at_ms` | integer | Конец ответа относительно начала аудио, в миллисекундах |
| `status` | varchar(20) | `completed` или `interrupted` |

Снимки названия и категории сохраняются отдельно от связи с `question`, чтобы старый результат оставался понятным после редактирования или удаления вопроса.

### `question_evaluation_rubric`

Эталон и критерии конкретного вопроса. Таблица не зависит от выбранной LLM, поэтому модель можно менять без миграции данных.

| Поле | Тип | Что хранится |
|---|---|---|
| `id` | integer | Идентификатор рубрики |
| `question_id` | integer, unique FK | Вопрос; при удалении вопроса рубрика удаляется каскадно |
| `reference_answer` | text | Краткий технически корректный эталон ответа |
| `required_points` | json | Список обязательных тезисов |
| `common_mistakes` | json | Типичные ошибки, которые должна заметить модель |

### `training_session_transcript`

Неизменяемый результат GigaAM для одного сегмента ответа.

| Поле | Тип | Что хранится |
|---|---|---|
| `id` | integer | Идентификатор расшифровки |
| `segment_id` | integer, unique FK | Сегмент; при его удалении расшифровка удаляется каскадно |
| `model` | varchar(120) | Фактически использованная ASR-модель |
| `text` | text | Итоговый русский текст |
| `words` | json | Слова и абсолютные таймкоды `startMs`/`endMs` внутри общей записи |
| `pauses` | json | Границы и длительность пауз от 450 мс |
| `metrics` | json | Длительность, время речи, число пауз, темп и слова-паразиты |
| `created_at` | timestamp | Когда получена расшифровка |

### `training_session_evaluation`

Структурированная оценка одного ответа. Она хранится отдельно от расшифровки, поэтому в будущем можно повторно оценивать уже готовый текст другой LLM без нового распознавания аудио.

| Поле | Тип | Что хранится |
|---|---|---|
| `id` | integer | Идентификатор оценки |
| `segment_id` | integer, unique FK | Оцениваемый сегмент |
| `provider` | varchar(50) | Адаптер запуска, сейчас `ollama` |
| `model` | varchar(120) | Фактически использованная LLM, сейчас `qwen3.5:9b-q4_K_M` |
| `attempts` | smallint | С какой попытки получен корректный ответ, максимум 3 |
| `total_score` | smallint | Итог вопроса от 0 до 100 |
| `criteria` | json | Баллы по семи критериям с фиксированными максимумами |
| `verdict` | text | Краткий общий вывод |
| `strengths` | json | Что в ответе получилось хорошо |
| `recommendations` | json | Конкретные действия для улучшения |
| `missing_topics` | json | Упущенные технические темы |
| `created_at` | timestamp | Когда выполнена оценка |

## Последовательность локального анализа

1. После `complete` Symfony ставит `AnalyzeTrainingSession` в Redis Messenger и сохраняет `analysis_status=queued`.
2. Worker меняет статус на `transcribing` и вызывает локальный FastAPI-адаптер GigaAM.
3. GigaAM возвращает все сегменты и гарантированно выгружается из памяти до завершения HTTP-запроса.
4. Symfony сохраняет `training_session_transcript`, меняет статус на `evaluating` и только тогда вызывает Qwen через Ollama.
5. Для каждого вопроса сохраняется `training_session_evaluation`, затем средний балл попадает в `training_session.analysis_score`.
6. Qwen выгружается командой `keep_alive: 0`. При трёх неудачных или зацикленных ответах сохраняются код и текст ошибки, а интерфейс предлагает повторить анализ.

## Аудиофайлы

- Браузер запрашивает только микрофон: `audio: true`, `video: false`.
- Одна попытка создаёт одну непрерывную запись голоса на все вопросы.
- Файлы сохраняются в `var/audio`, вне публичной директории `public`.
- Клиент получает запись только через контролируемый API-метод Symfony.
- `GET /api/sessions/{id}/audio` отдаёт поток с поддержкой byte ranges для перемотки WaveSurfer.js.
- Вся тренировка записывается одним файлом; выбор вопроса перемещает плеер к `started_at_ms` и останавливает его на `ended_at_ms`.
- В БД не сохраняется содержимое аудио и не раскрывается путь на сервере.
- Камера, видео и запись экрана нигде не запрашиваются и не хранятся.

## Данные локального чата

- История чата не сохраняется в PostgreSQL: она живёт только в памяти открытой вкладки браузера и передаётся в `/api/chat/messages` при очередном запросе.
- На сервер отправляются не более 20 сообщений и не более 24 000 символов суммарно; API повторно проверяет роли и размеры строк.
- Голосовой ввод сохраняется в `var/audio` только на время вызова GigaAM и удаляется в блоке очистки как после успеха, так и после ошибки.
- Распознанный текст возвращается в браузер и сначала помещается в поле ввода. Qwen вызывается только после явной отправки этого текста пользователем.
- Перед запуском GigaAM Symfony выгружает Qwen. После распознавания GigaAM также освобождает память, поэтому обе модели не находятся в памяти одновременно.

## Начальные данные

Первая миграция создаёт восемь демонстрационных вопросов из GUI-прототипа и одну тренировку «PHP Backend — пробное собеседование». Это делает приложение полезным сразу после `doctrine:migrations:migrate`.
